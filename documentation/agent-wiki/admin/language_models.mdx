Agent Wiki needs a language model provider. Until one is configured, agents, triggers,
and Auto Organize sit idle — there's no error, they simply never do anything.

Go to **Admin → Language Models** to manage provider credentials and set the model agents use.

## What the model does here

Agent Wiki uses this model to:

- Evaluate [trigger](/agent-wiki/automate/triggers) conditions written in plain English, on every relevant change
- Write the notification text a trigger sends, grounded in what actually changed
- Apply natural-language document updates, including the ones agents request over MCP
- Merge concurrent edits when two writers touch the same page
- Judge and apply [Auto Organize](/agent-wiki/automate/auto_organize) proposals

So provider choice and rate limits affect the responsiveness of the whole product, not one feature.
Choose a capable model. To control cost, use a cheaper model for ingestion.

## A cheaper model for ingestion

Ingestion generates more model calls than everything else combined,
and its work — matching pushed documents to pages and merging them in — doesn't need your strongest model.
On the [Onyx Integration](/agent-wiki/admin/onyx_integration)
page you can select a separate model just for the ingestion pipeline; pick a cheap, fast one (e.g. Luna)
and keep the more capable default for daily usage. The ingestion model has to come from the providers enabled here.

## Per-user overrides

Users can pick a different model for their own chats under **Settings**.
The admin setting is the default and the model everything automated uses;
the override only affects that person's interactive sessions.
