## Guide

**Note:** On Windows, the commands differ slightly, but the steps are the same.

<Steps>
  <Step title="Install requirements">
    - [Git](https://git-scm.com/downloads)
    - [Docker (with Compose)](https://docs.docker.com/get-docker/)
  </Step>

  <Step title="Clone the Onyx repo">
    ```bash
    git clone --depth 1 https://github.com/onyx-dot-app/onyx.git
    cd onyx/deployment/docker_compose
    ```
  </Step>

  <Step title="Create the .env file">
    Copy the template and edit the values you need:

    ```bash
    cp env.template .env
    ```

    `IMAGE_TAG` selects the Onyx version. It defaults to `latest`.
    Change the `S3_AWS_ACCESS_KEY_ID` and `S3_AWS_SECRET_ACCESS_KEY` pair before you use the deployment in production.
    See the [configuration reference](/deployment/configuration/configuration) for all settings.
  </Step>

  <Step title="Launch Onyx">
    To pull images from Docker Hub and start Onyx:

    ```bash
    docker compose up -d
    ```

    To build images from source instead:

    ```bash
    docker compose up -d --build --force-recreate
    ```

    <Warning>
      If you first launched Onyx with the old `onyx-stack` project name,
      add `-p onyx-stack` to your command so Compose reuses your volumes.

      For example: `docker compose -p onyx-stack up -d`.
    </Warning>
  </Step>
</Steps>

After the containers start, Onyx initializes its database and search index.
Then open [localhost:3000](http://localhost:3000).

## Upgrading

Update the Compose files and the images to the same release. If you change only `IMAGE_TAG`,
the new images run on the old Compose files and miss new services and settings.
The [Onyx CLI](/deployment/local/onyx_cli#upgrade) does these steps for you.

<Steps>
  <Step title="Read the release notes">
    Read the Deployment Changes of each release after your current version in the [Release Notes](/changelog).
    Some releases need `.env` changes,
    such as the [Object Store Migration](/admins/advanced_configs/object_store_migration) in `v5.0.0`.
  </Step>

  <Step title="Update the Compose files">
    In `onyx/deployment/docker_compose`, check out the tag of the new release, for example `v5.0.4`.
    [GitHub Releases](https://github.com/onyx-dot-app/onyx/releases) lists the tags.

    If `git status` shows edits to files that Git tracks, run `git stash` first.

    ```bash
    git fetch --depth 1 origin tag <version>
    git switch --detach <version>
    ```

    If you ran `git stash`, run `git stash pop` to apply your edits again. If it reports a conflict,
    fix the marked lines before you restart Onyx.
  </Step>

  <Step title="Update the .env file">
    Git does not track `.env`, so the checkout keeps it. Do not replace it with a new copy of `env.template`.
    The template holds settings for a new install, such as `MINIO_REPLICAS=0`.

    Set `IMAGE_TAG` to the same release, for example `IMAGE_TAG=v5.0.4`.
    Make the `.env` changes from the release notes in the same edit.
  </Step>

  <Step title="Restart Onyx">
    Run the command that you use to start Onyx, with all its `-f`, `-p`, and `--build` options. For the default setup:

    ```bash
    docker compose up -d
    ```
  </Step>
</Steps>

## Onyx Lite

Onyx Lite runs the core chat experience with only PostgreSQL. It starts no OpenSearch, Redis, model servers,
object store, or background workers. Connectors and search over indexed documents are disabled. Chat, user file uploads,
Projects, Agent knowledge, and the code interpreter still work.

Add the Lite overlay to the launch command:

```bash
docker compose -f docker-compose.yml -f docker-compose.onyx-lite.yml up -d
```

The overlay moves the removed services to Compose profiles. For example, `--profile opensearch` brings OpenSearch back.
The header of `docker-compose.onyx-lite.yml` lists the profiles.

## Enabling Onyx Craft

Craft adds isolated sandbox containers and an egress proxy to the Docker Compose deployment.
Craft requires a Business or Enterprise license and does not run on Onyx Lite.
Use the [Craft Docker Compose guide](/deployment/local/craft_docker_compose) for both new and existing installations.
