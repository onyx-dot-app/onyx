## Overview

OpenSearch is the document index Onyx uses for keyword and vector retrieval. It replaced Vespa.
Every full deployment needs one OpenSearch cluster. Onyx Lite runs without a document index,
so connectors and search over indexed documents are disabled there.

In the Onyx **Helm** chart, the `opensearch` section defines the OpenSearch instance,
and the `auth.opensearch` section defines its credentials. Both are enabled by default. When you install the chart,
Helm starts a single-node OpenSearch cluster and sets the host, port,
and credential environment variables on every Onyx service.

In the Onyx **Docker Compose** file, the `opensearch` service defines both the instance and its credentials.
The application reads the same environment variables from your `.env` file.

## Auth

OpenSearch requires initial admin credentials. Onyx uses them to authenticate every request.
The password must have at least 8 characters, with at least one uppercase letter, one lowercase letter, one digit,
and one special character.

With **Docker Compose**, no action is required.
The Compose file sets an initial password that matches the default Onyx uses when `OPENSEARCH_ADMIN_PASSWORD` is not
set.

To use a different password, set `OPENSEARCH_ADMIN_PASSWORD` in the `.env` file before the first start.
The Compose file passes it to both OpenSearch and the Onyx services.

With **Helm**, there is no default password. Set one in your values file:

```yaml values.yaml
# Other overrides you may have.

configMap:
  # Other overrides you may have.

  OPENSEARCH_ADMIN_PASSWORD: <your chosen password>

auth:
  # Other overrides you may have.

  opensearch:
   values:
     opensearch_admin_password: <your chosen password>
```

## Configuration variables

| Variable | Default | Description |
| --- | --- | --- |
| `OPENSEARCH_HOST` | `localhost` | Hostname of the OpenSearch cluster. The Compose file and Helm chart set it for you. |
| `OPENSEARCH_REST_API_PORT` | `9200` | REST API port. |
| `OPENSEARCH_ADMIN_USERNAME` | `admin` | Username for HTTP basic auth. |
| `OPENSEARCH_ADMIN_PASSWORD` | Compose default | Password for HTTP basic auth. |
| `USING_AWS_MANAGED_OPENSEARCH` | `false` | Set to `true` for an Amazon OpenSearch Service domain. |

## Startup after a restart

On a self-hosted OpenSearch, Onyx creates the document index with the `index.store.preload` setting.
When OpenSearch starts, it reads the vector, graph, and keyword files of the index into memory.
The index accepts searches after this read is complete. Until then, searches return an error. After the read,
most of the data a search uses is already in memory, so early searches are close to normal speed.
Stored text is not preloaded. A search still reads the text of its top results from disk.

Without the preload, the index accepts searches sooner,
but each early search reads its own parts of the index from disk. On a large index,
search can then stay slow for several minutes after a restart.

The preload makes startup longer. The extra time is the preloaded file size divided by the disk read speed. For example,
15 GB at 125 MB/s (the base throughput of an AWS gp3 volume) takes about 2 minutes.

- The setting applies to indexes that Onyx creates. An existing index keeps its settings until a reindex
  creates a new index.
- Onyx does not set it when `USING_AWS_MANAGED_OPENSEARCH` is `true`.
- Give OpenSearch enough memory to hold the preloaded files. If memory is too small, OpenSearch removes them
  from memory again during search. See [Resourcing](/deployment/getting_started/resourcing).

## If using your own managed OpenSearch

[If you provisioned a managed instance](/deployment/local/terraform#opensearch-optional),
you do not need Helm to start an OpenSearch cluster. Disable it in your Helm values file:

```yaml values.yaml
# Other overrides you may have.

opensearch:
  enabled: false

auth:
  # Other overrides you may have.

  opensearch:
    enabled: false
```

Then set the connection variables for your cluster. Helm passes them to every Onyx service.

```yaml values.yaml
# Other overrides you may have.

configMap:
  # Other overrides you may have.

  OPENSEARCH_ADMIN_USERNAME: "<the username you set when creating the OpenSearch cluster>"
  OPENSEARCH_ADMIN_PASSWORD: "<the password you set when creating the OpenSearch cluster>"
  OPENSEARCH_HOST: "<the host name of the OpenSearch cluster, as reported on the AWS console; do not include https://>"
  OPENSEARCH_REST_API_PORT: "443"
  USING_AWS_MANAGED_OPENSEARCH: "true"
```

See [External Services](/deployment/production/external_services) for other managed OpenSearch options.
