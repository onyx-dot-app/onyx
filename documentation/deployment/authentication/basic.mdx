Email and password sign-in is always on in Onyx.

- The first user who signs up becomes the admin.
- Every later user signs up with an email and password, or signs in with SSO if you add a provider.
- Admins invite users and approve requests at **Admin Panel → Permissions → Users**.

<Note>
  The `AUTH_TYPE` environment variable is no longer used. Onyx ignores it and logs a warning at startup.
  Remove it from your deployment. SSO is configured in the admin panel, not with `AUTH_TYPE`.
</Note>

## Sign-Up Controls

Set these in **Admin Panel → Organization → Security & Hardening**, in the **Authentication** section:

- **Restrict Open Sign-Up**: only invited users can create an account.
- **Allowed Email Domains**: only emails on these domains can sign up or sign in. You can also set `VALID_EMAIL_DOMAINS` as a comma-separated list in the environment.
- **Disable Password Login & Signup**: everyone signs in and registers through SSO only.
  Requires at least one enabled SSO provider.

## Password Requirements

Set the password policy in **Admin Panel → Organization → Security & Hardening**, in the **Password Policy** section.
The policy applies to new passwords for email and password accounts only.

| Setting                     | Environment variable            | Default |
| --------------------------- | ------------------------------- | ------- |
| Minimum Password Length     | `PASSWORD_MIN_LENGTH`           | `8`     |
| Maximum Password Length     | `PASSWORD_MAX_LENGTH`           | `64`    |
| Require Uppercase Letter    | `PASSWORD_REQUIRE_UPPERCASE`    | `false` |
| Require Lowercase Letter    | `PASSWORD_REQUIRE_LOWERCASE`    | `false` |
| Require Number              | `PASSWORD_REQUIRE_DIGIT`        | `false` |
| Require Special Characters  | `PASSWORD_REQUIRE_SPECIAL_CHAR` | `false` |

A value you set in the admin panel overrides the environment variable.
An empty setting falls back to the environment value.

## Email Verification

Set `REQUIRE_EMAIL_VERIFICATION=true` to make new users confirm their email address before they can sign in.
Onyx needs an SMTP server to send the verification email.

<Tabs>
  <Tab title="Docker Compose">
    In `docker-compose.yml`, add these variables to the `api_server` service:

    ```yaml
    REQUIRE_EMAIL_VERIFICATION: "true"
    SMTP_SERVER: smtp.gmail.com  # Your SMTP server
    SMTP_PORT: "587"
    SMTP_USER: your-email@company.com
    SMTP_PASS: your-password-or-app-password
    EMAIL_FROM: your-email@company.com
    ```
  </Tab>

  <Tab title="Helm">
    In `values.yaml`, set the SMTP password as a secret and the other values in the config map:

    ```yaml
    auth:
      smtp:
        enabled: true
        values:
          smtp_pass: your-password-or-app-password
    configMap:
      REQUIRE_EMAIL_VERIFICATION: "true"
      SMTP_SERVER: smtp.gmail.com
      SMTP_PORT: "587"
      SMTP_USER: your-email@company.com
      EMAIL_FROM: your-email@company.com
    ```
  </Tab>
</Tabs>

If you use Gmail, create an [App Password](https://support.google.com/accounts/answer/185833) and use it as `SMTP_PASS`.
Set `SMTP_STARTTLS=false` if your server does not support STARTTLS.

The same SMTP settings send invitation emails.
Set `ENABLE_EMAIL_INVITES=true` to email new users when an admin invites them.

## Sessions

A session lasts 7 days by default. Set `SESSION_EXPIRE_TIME_SECONDS` to change this.

Turn on **Sync Session Expiry with Identity Provider** in **Security & Hardening** to end Onyx sessions when the
identity provider session ends. This applies to SSO sign-ins only.
