<Note>
  The Coding Agent supports **public** GitHub repositories only.
</Note>

The Coding Agent action lets your Agents investigate a GitHub repository and answer questions about its codebase.
It downloads the repository into an isolated sandbox, explores the code with shell commands,
and returns a written answer.

## Capabilities

- **Codebase Q&A**: Explain how a repository implements a feature and where the logic lives
- **Code investigation**: Trace data flow and interactions between components
- **Onboarding**: Summarize a project's structure and key modules

## How It Works

When the LLM invokes the Coding Agent, Onyx:

<Steps>
  <Step title="Downloads the repository">
    Onyx downloads an archive of the repository's default branch (no Git history)
    into an isolated session in the [Code Interpreter](/admins/actions/code_interpreter) service.
  </Step>

  <Step title="Investigates the code">
    An LLM loop runs shell commands to explore the code.
  </Step>

  <Step title="Returns an answer">
    The loop ends with a written answer based on its findings.
  </Step>
</Steps>

One investigation runs for up to 25 minutes. After that,
the Coding Agent stops exploring and writes its answer from what it found.
The sandbox session is removed when the investigation ends.

## Configuration

The Coding Agent is a built-in action. It needs no credentials.

<Steps>
  <Step title="Confirm the Code Interpreter is connected">
    The Coding Agent runs in the same sandbox service as the [Code Interpreter](/admins/actions/code_interpreter).
    Open **Admin Panel > Code Interpreter** and confirm the status is **Connected**.
    The action does not appear in chat while the service is disconnected or unhealthy.
  </Step>

  <Step title="Turn it on for default Chat">
    Go to **Admin Panel > Chat Preferences > Actions & Tools** and turn on **Coding Agent**.
  </Step>

  <Step title="Turn it on for custom Agents">
    In the [Agent editor](/admins/agents/overview),
    open **Actions** and turn on **Coding Agent** for each Agent that should use it.
  </Step>
</Steps>

## Using the Coding Agent

The LLM decides when to invoke the Coding Agent based on the user's request. Users do not need to invoke it explicitly.

<Tip>
  Name the repository you want analyzed, as a GitHub URL or as `owner/repository`. For example:
  *"Using the repository at https://github.com/onyx-dot-app/onyx, explain how the connector indexing pipeline works."*
</Tip>

## Limitations

- **Public repositories only**: The Coding Agent cannot download private repositories. The investigation fails with
  a "Repository or branch not found" error.
- **Default branch only**: The Coding Agent reads the current state of the default branch. It does not read Git
  history, other branches, pull requests, or issues.
