The Azure Data Lake Storage connector indexes the files in one container of an Azure Data Lake Storage Gen2 account.
With permission sync, it also mirrors who can read each file in Azure.

## What gets indexed

The connector indexes the files in one container, or in one directory of it with **Path Prefix**.
Each file becomes one document that links to the file's blob URL,
`https://<account>.blob.core.windows.net/<container>/<path>`. Each refresh reads only the files that changed,
and the prune job removes the documents of deleted files.

<Accordion title="Supported file types">
  Onyx indexes files with the following extensions:

  | Kind         | Extensions                                                                       |
  | ------------ | -------------------------------------------------------------------------------- |
  | Documents    | `.pdf`, `.docx`, `.pptx`, `.eml`, `.epub`, `.html`                               |
  | Spreadsheets | `.xlsx`, `.xlsm`, `.csv`, `.tsv`                                                 |
  | Text         | `.txt`, `.md`, `.mdx`, `.conf`, `.log`, `.json`, `.xml`, `.yml`, `.yaml`, `.sql` |
  | Images       | `.png`, `.jpg`, `.jpeg`, `.webp`                                                 |

  Onyx indexes image files only when **Extract & Caption Images** is on.
  See [Image Processing](/admins/advanced_configs/search_configs#image-processing).
</Accordion>

## Before you begin

You need a storage account with **hierarchical namespace** enabled, and the name of the container to index.
Choose how the connector signs in:

| Method                         | What you give Onyx                                     | Permission sync |
| ------------------------------ | ------------------------------------------------------ | --------------- |
| **Client Secret**              | A Microsoft Entra app registration and a client secret | Yes             |
| **Certificate Authentication** | A Microsoft Entra app registration and a `.pfx` file   | Yes             |
| **Account Key**                | The storage account name and one of its access keys   | No              |

An account key works only for its own storage account. To get one, open the storage account in the Azure portal,
go to **Security + networking → Access keys**, and copy one of the two keys.

## Set up the app registration

Skip this section if you use an account key.

<Steps>
  <Step title="Register the application">
    Register an application in Microsoft Entra, and create a client secret or a certificate for it.
    See [Microsoft 365 Setup](/admins/connectors/official/microsoft-365/setup).
    An app registration that already serves a Microsoft 365 connector also works here.
  </Step>

  <Step title="Give the application read access">
    In the Azure portal, open the container and go to **Access Control (IAM)**.
    Give the application the **Storage Blob Data Reader** role. For indexing only,
    read and execute ACL access to the files and their directories is also enough.
  </Step>

  <Step title="Add the permission sync grants">
    Do this step only if you use permission sync.

    - The **Storage Blob Data Reader** role on the container, even if indexing uses ACL access.
    - The **Reader** role on the storage account, so that Onyx can read the role and deny assignments.
    - The Microsoft Graph application permissions **User.Read.All** and **GroupMember.Read.All**, and
    **Member.Read.Hidden** if groups with hidden membership have access to files. Then grant admin consent.
  </Step>
</Steps>

## Configure the connector in Onyx

<Steps>
  <Step title="Enter the storage account">
    Go to **Admin Panel → Connectors** and select **Azure Data Lake Storage**. In **Storage Account Name**,
    enter the name of the storage account, for example `contosodata`.
  </Step>

  <Step title="Select or create an authentication account">
    Under **Authentication Account**, select a saved account,
    or select **New Azure Data Lake Storage Account** and fill in the tab for your method.

    <img className="rounded-image" src="/assets/admins/connectors/azure_datalake/credential_methods.webp" alt="Azure Data Lake Storage connector form with the Client Secret, Certificate Authentication, and Account Key tabs"/>
  </Step>

  <Step title="Choose the content and the access">
    Enter the **Container Name**. To index one directory only, enter its path in **Path Prefix**,
    for example `reports/2026`.

    Under **Document Access**, select **Sync with Azure Data Lake Storage** to mirror the Azure access of each file.
    This option is not available with an account key.
  </Step>

  <Step title="Run the checks and create the connector">
    Select **Start Checks**. Onyx checks sign-in, the container, the path prefix, and one file read.
    With permission sync, it also checks ACL reads, the storage account in Azure Resource Manager, role assignments,
    and Entra users and group members. A failed check says what to fix.

    Select **Create Connector**.
  </Step>
</Steps>

## Permission sync

With **Sync with Azure Data Lake Storage**, an Onyx user finds a file in search only if they can read it in Azure.
Onyx grants file access to:

- Users and groups with a role that reads blob data, such as **Storage Blob Data Reader**,
  at the container scope or above
- Users and groups that the ACLs let read the file and traverse each directory above it
- Every user in the Entra tenant, when the ACL `other` class can read the file
- Every Onyx user, when the container allows anonymous read access

A deny assignment removes access from both roles and ACLs. An Entra user principal name, or the mail address of a guest,
must match the user's email in Onyx.

<Note>
  Permission sync is a paid feature: the Business and Enterprise tiers on Onyx Cloud,
  and the Enterprise Edition when self-hosted. It needs an app registration account.
</Note>

The document sync runs every hour. The group sync runs every 30 minutes.
Self-hosted deployments can change the intervals with `AZURE_DATALAKE_PERMISSION_DOC_SYNC_FREQUENCY` and
`AZURE_DATALAKE_PERMISSION_GROUP_SYNC_FREQUENCY`, in seconds. A new file stays private until the next document sync.
A file that "everyone except" some users or groups can read appears for those users after the next group sync.

Onyx cannot evaluate ABAC conditions. It gives no access through a role assignment with a condition,
and it applies a deny assignment with a condition everywhere.
Onyx keeps a file private when it cannot read the members of a group that the file depends on,
or when the file needs more than 5,000 users and groups.

## Limits

| Limit     | Value                       | Notes                                                                                                          |
| --------- | --------------------------- | -------------------------------------------------------------------------------------------------------------- |
| File size | 20 MB                       | Onyx skips larger files. Self-hosted deployments can change this with `BLOB_STORAGE_SIZE_THRESHOLD`, in bytes. |
| Scope     | One container per connector | Create one connector for each container.                                                                       |

## Troubleshooting

<AccordionGroup>
  <Accordion title="Onyx cannot reach the storage account">
    Onyx cannot connect to `<account>.dfs.core.windows.net`. Check the **Storage Account Name**.
  </Accordion>

  <Accordion title="This account key belongs to a different storage account">
    Use a key of the storage account in **Storage Account Name**, or use an app registration.
  </Accordion>

  <Accordion title="The credential cannot read a path">
    Give the application the **Storage Blob Data Reader** role on the container,
    or read and execute ACL access to the files and their directories.
  </Accordion>

  <Accordion title="The app registration cannot see the storage account in Azure Resource Manager">
    Give the application the **Reader** role on the storage account.
  </Accordion>

  <Accordion title="A file that users can read in Azure is not in their search results">
    Wait for the next document sync and group sync.
    Then make sure that the user's Onyx email matches their Entra account.
  </Accordion>
</AccordionGroup>
