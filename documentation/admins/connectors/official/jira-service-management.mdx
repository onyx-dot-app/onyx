## How it works

Jira Service Management stores each service desk in a Jira project.
The connector lists the service desks that its account can read, maps each desk to its Jira project,
and indexes all issues in that project, including issues that are not customer requests.
Onyx checks for new and changed issues on the connector's refresh schedule. The default is every **30** minutes.

For every issue, this connector pulls:

- Title
- Description
- [Common fields](#indexed-metadata)
- Comments

The connector uses the Jira search and issue APIs after it resolves the service desks.
It can index only the content that its Jira account can access.
An API token does not give its owner additional Jira permissions.

<Warning>
  This connector supports Jira Service Management Cloud only.
  Jira Data Center does not provide the Jira Cloud issue fetch that this connector uses.
  The connector rejects a Data Center credential instead of indexing incomplete data.
</Warning>

## Before you start

Use a dedicated Jira account for the connector.
This makes its access easier to review and prevents a personal account change from stopping the connector.
The account must be a Jira Service Management agent.
A customer account sees only its own requests and cannot index a service desk.

## Grant access in Jira

Ask a Jira administrator to complete these steps while signed in to Jira:

<Steps>
  <Step title="Grant service desk access">
    Add the connector account to each service desk that you want to index.
    Grant the account a role that can view all requests, such as **Service Desk Team**.
    Confirm that the account can open the service desk and read representative requests.
  </Step>

  <Step title="Grant Jira project access">
    Grant **Browse Projects** on every Jira project that backs an indexed service desk.
    Also grant access to each issue security level used by the indexed requests,
    and to each restricted comment that you want to index.
  </Step>

  <Step title="Test restricted content">
    Sign in as the connector account.
    Confirm that it can open representative requests and comments from each restriction type that you want to index.
  </Step>
</Steps>

## Create the API token

Create an API token from the connector account.
Follow Atlassian's [API token
instructions](https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/).

The connector calls two APIs:

- The Jira Service Management REST API, to list service desks.
- The Jira platform REST API, to search and fetch the requests.

If you create a token with scopes, grant the scopes that both APIs require.
The Jira platform scope for issue search and fetch is `read:jira-work`,
and the Jira Service Management scope for service desk request data is `read:servicedesk-request`.
Enable **Scoped API Token** in Onyx only when the token has these scopes.

If Atlassian does not offer the Jira Service Management scope for your scoped token,
create an unscoped API token and leave **Scoped API Token** off.

## Configure the connector

<Steps>
  <Step title="Provide credentials">
    Go to **Admin Panel → Connectors** and select **Jira Service Management**.
    Select **New Jira Service Management Account**, then enter the connector account's email address and API token.
    These values are saved with the connector, so there is no separate account creation step.
  </Step>

  <Step title="Configure the source">
    Enter the Jira site in **Site URL**. The URL is usually `https://your-domain.atlassian.net`.
    Enable **Scoped API Token** if you created a scoped token.
  </Step>

  <Step title="Choose what to index">
    Select one indexing mode:

    - **Everything** indexes all issues in every Jira project that backs a service desk the connector account can read.
    - **Project** indexes all issues in one Jira project. Enter its project key, such as `PROJ`.

    To exclude comments from specified accounts, add their email addresses to **Comment Email Blacklist**.
    Jira Cloud can hide comment author email addresses. When it does, the connector cannot match the address,
    so the blacklist cannot guarantee that the comment is excluded.
  </Step>

  <Step title="Choose document access">
    Under **Document Access**, select **Everyone in Your Organization** or **Specific Groups**.
    This connector does not sync Jira permissions. Document Access applies to the entire connector:
    every reader can see every indexed issue and comment.
    Choosing **Specific Groups** does not preserve Jira issue security levels or restricted comments.
    Select only groups authorized to read all indexed content.
  </Step>

  <Step title="Create the connector">
    Select **Create Connector**. It is enabled when the required checks pass.
  </Step>
</Steps>

## Indexed metadata

```
- Issue Key
- Priority
- Status
- Resolution
- Labels
- Created
- Updated
- Due Date
- Issue Type
- Resolution Date
- Parent Issue Key
- Project Name
- Project Key
- Reporter
- Reporter Email
- Assignee
- Assignee Email
- Service Desk ID
```

## Troubleshooting

- **No service desk is visible.** The connector account cannot read a service desk in the selected scope.
  Check the service desk role and **Browse Projects** access.
- **HTTP 403.** The token is valid,
  but it lacks a required scope or the account lacks access to a service desk or Jira project.
- **Data Center credential rejected.** Use Jira Cloud, or use the Jira connector for a Data Center deployment.
