An OpenAPI plugin connects Onyx to a REST API. You give Onyx an [OpenAPI](https://swagger.io/specification/) schema,
and Onyx turns each operation in the schema into a tool.
Agents read the operation descriptions and parameters to decide when and how to call the API.

OpenAPI plugins work in default Chat and in custom agents. They are not available in Craft. For Craft,
use an [MCP server](/admins/plugins/mcp) or a [custom Craft App](/admins/plugins/craft_apps#custom-apps).

Users with the **Manage Actions** permission can add and edit OpenAPI plugins.
Only full admins can change default Chat availability.

Use an OpenAPI plugin for internal services, such as a ticket system or an inventory API, when no MCP server exists.

## Add an OpenAPI plugin

<Steps>
  <Step title="Paste the schema">
    Go to **Admin Panel → Integrations**, click **Add**, then select **OpenAPI App**. Click **Add schema**,
    paste the schema, and click **Continue**. Onyx reads the schema and lists its operations.

    The schema must include:

    - A `servers` entry with the base URL of the API.
    - An `operationId` for each operation. Onyx uses it as the tool name.
    - A `summary` or `description` for each operation, so the agent knows when to use it.

    The Onyx API server must be able to reach the server URL.
  </Step>

  <Step title="Name and describe the integration">
    Enter a **Name** and a **Description**.
    Users see the description in the integration list and on the integration page.
    The agent reads the operations in the schema, not this description.
  </Step>

  <Step title="Set the sign-in">
    Select a **Sign-in Mode** and a **Sign-in Method**. See [Sign-in](#sign-in).
  </Step>

  <Step title="Add the plugin">
    Select the **Owner** if the page shows it, then click **Add**. To turn the integration on for each user,
    so that default Chat uses it,
    set its install setting to **Installed** or **Required** on **Admin Panel → Integrations**.
    Only users with the organization-wide **Manage Actions** permission can change the install setting.
  </Step>
</Steps>

## Sign-in

| Sign-in Mode | Sign-in Method | Effect |
| --- | --- | --- |
| **No sign-in** | None | Onyx sends requests without credentials. |
| **One account for the organization** | **API key** | Onyx adds the headers that you set, such as `Authorization: Bearer {api_key}`, to every request. An admin enters the values on the **Configuration** tab. All users share these credentials. |
| **One account for the organization** | **OAuth** | An admin connects one account on the **Configuration** tab. |
| **Each user signs in** | **API key** or **OAuth** | Each user connects their own account in [Customize → Integrations](/overview/core_features/plugins) before the agent can call the API for them. |
| **Each user signs in** | **Onyx login** | Onyx sends the user's Onyx sign-in token to the API. Only an admin who manages actions for the whole organization can select it. |

For **API key**, put each credential in braces in the **Header Value**. Each placeholder becomes a credential field.
Click **Add Header** to send more headers.

For **OAuth**, create an OAuth client in the provider with this redirect URI:

```text
https://<your-onyx-domain>/oauth-config/callback
```

Then enter the **Authorization URL**, **Token URL**, **Client ID**, and **Client Secret**. Optionally, enter **Scopes**.

## Request placeholders

Use these placeholders anywhere in the schema, for example in the server URL, a path, or a parameter default.
Onyx replaces them with the values of the current request at call time.

| Placeholder | Value |
| --- | --- |
| `CHAT_SESSION_ID` | The ID of the current chat session |
| `MESSAGE_ID` | The ID of the current message |
| `USER_ID` | The ID of the current user |
| `USER_EMAIL` | The email address of the current user |

## Manage the plugin

| Tab | Contents |
| --- | --- |
| **Overview** | Name, description, owner, **Install Setting**, **Enabled**, and **Delete**. |
| **Configuration** | The schema, the sign-in, and **Users Can Save Always Allow**. |
| **Actions** | The operations that Onyx found in the schema, each with **Allow**, **Ask**, or **Blocked**. |

<img className="rounded-image" src="/assets/admins/plugins/integration_openapi_actions_tab.webp" alt="The Actions tab with the operations from an OpenAPI schema"/>

To add, remove, or change an operation, edit the schema on the **Configuration** tab.
Onyx syncs the actions again when you save a changed schema.

Changing the install setting of the integration does not remove it from custom agents.
To remove the integration from all agents, delete it on the **Overview** tab.

<Note>
  In Terraform, `onyx_custom_tool.enabled` sets default Chat availability. It does not change custom-agent attachments.
</Note>

## Use the plugin in custom agents

Open the agent editor and select **Add an integration** under **Actions**. See [Agents](/admins/agents/overview).

## Import a schema from an MCP bridge

[mcpo](https://github.com/open-webui/mcpo) exposes a local MCP server as an OpenAPI service.
Use this approach with self-hosted Onyx when your MCP server uses stdio instead of HTTP.

For example, [ctxd's Docker MCP server](https://github.com/ctxddev/ctxd-agent-plugin)
synchronizes source content and exposes read tools. After a source edit completes synchronization,
Onyx can call the read operation again to get the changed content.

Start with a working, authenticated mcpo bridge. The import steps use its existing OpenAPI endpoint.
For the ctxd example, install this dependency set in a separate Python 3.12 virtual environment on the bridge host:

```bash
uv pip install mcpo==0.0.20 mcp==1.17.0 fastapi==0.116.1 pydantic==2.11.7
```

Before you export the schema:

- Run the MCP server through mcpo with an API key. Use the server's setup instructions and mcpo's configuration guide.
- For ctxd 0.1.16, add `"disabledTools": ["grep"]` to its mcpo server configuration. This example uses the read and path tools.
- Give the bridge a non-loopback address that the Onyx API server can reach.
  The default **SSRF Protection** level blocks loopback addresses such as `127.0.0.1`,
  even when both run on the same host. If Onyx runs in Docker, a loopback address refers to its container.
- Share only source content that every user of the agent may read. The authorization header uses one shared credential.

<Steps>
  <Step title="Export the bridge schema">
    Set `MCP_BRIDGE_URL` to the server-specific base URL, such as `https://bridge.example.com/ctxd`.
    Set `MCP_BRIDGE_KEY` to the bridge API key in your shell environment.

    Run this command from a workstation that can reach the bridge. It writes `onyx-openapi.json` without the API key.

    ```bash
    uv run --no-project --with jsonref==1.1.0 python - <<'PY' > onyx-openapi.json
    import json
    import os
    import urllib.request

    import jsonref

    base_url = os.environ["MCP_BRIDGE_URL"].rstrip("/")
    request = urllib.request.Request(
        base_url + "/openapi.json",
        headers={"Authorization": "Bearer " + os.environ["MCP_BRIDGE_KEY"]},
    )
    with urllib.request.urlopen(request, timeout=30) as response:
        schema = json.load(response)

    # Onyx's model-facing tool schemas need their request properties inline.
    schema = jsonref.replace_refs(schema, proxies=False)
    schema["servers"] = [{"url": base_url}]
    print(json.dumps(schema, indent=2))
    PY
    ```

    The absolute `servers` URL preserves the bridge's server prefix.
    Inline references keep the operation parameters available to the agent.
    Export only a schema from a bridge you control.
  </Step>

  <Step title="Add the plugin">
    Follow [Add an OpenAPI plugin](#add-an-openapi-plugin) and paste the contents of `onyx-openapi.json`.
    Select **Custom Authorization Header**.
    Set the header name to `Authorization` and its value to `Bearer <bridge-api-key>`.

    Add the plugin to a custom agent. The generated operation names, such as `tool_read_post`, appear under **Tools**.
  </Step>

  <Step title="Check a source change">
    With ctxd, ask the agent to read a known source path, such as `local-files/source/guide.md`. Edit that source,
    wait for synchronization, and ask the agent to read the same path again.

    Check the tool result for the changed content.
    A removed source returns a source-not-found error after synchronization.
    OpenAPI plugins do not make these tools available in Craft.
  </Step>
</Steps>

## Example

Use this schema to add a plugin that creates and gets agents in Onyx. Replace the server URL with your Onyx API URL.

```json OpenAPI expandable
{
  "openapi": "3.1.0",
  "info": {
    "title": "Agents API",
    "version": "1.0.0",
    "description": "Minimal OpenAPI schema for creating and fetching agents in Onyx"
  },
  "servers": [
    {
      "url": "https://cloud.onyx.app/api"
    }
  ],
  "paths": {
    "/persona": {
      "post": {
        "summary": "Create Agent (Persona)",
        "operationId": "create_persona",
        "requestBody": {
          "required": true,
          "content": {
            "application/json": {
              "schema": {
                "type": "object",
                "properties": {
                  "name": { "type": "string" },
                  "description": { "type": "string" },
                  "document_set_ids": {
                    "type": "array",
                    "items": { "type": "integer" }
                  },
                  "is_public": { "type": "boolean" },
                  "tool_ids": {
                    "type": "array",
                    "items": { "type": "integer" }
                  },
                  "system_prompt": { "type": "string" },
                  "task_prompt": { "type": "string" },
                  "datetime_aware": { "type": "boolean" }
                },
                "required": [
                  "name",
                  "description",
                  "document_set_ids",
                  "is_public",
                  "tool_ids",
                  "system_prompt",
                  "task_prompt",
                  "datetime_aware"
                ]
              }
            }
          }
        },
        "responses": {
          "200": { "description": "Created" }
        }
      }
    },
    "/persona/{persona_id}": {
      "get": {
        "summary": "Get Agent (Persona) By ID",
        "operationId": "get_persona",
        "parameters": [
          {
            "name": "persona_id",
            "in": "path",
            "required": true,
            "schema": { "type": "integer" }
          }
        ],
        "responses": {
          "200": { "description": "OK" }
        }
      }
    }
  }
}
```
