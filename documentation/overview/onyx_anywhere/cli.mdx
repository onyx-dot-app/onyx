The Onyx CLI is a terminal interface for chatting with your Onyx Agents and searching your knowledge base.
It provides an interactive chat TUI for people and non-interactive commands for scripts and AI coding agents.
The CLI is available on all editions.

## Installation

### PyPI (recommended)

```shell
uv tool install onyx-cli
```

Or with pip:

```shell
pip install onyx-cli
```

<Card title="PyPI Package" icon="python" href="https://pypi.org/project/onyx-cli/">

</Card>

### Standalone Binaries

Standalone binaries for Linux, macOS, and Windows (amd64 and arm64)
are attached to each [`cli/v*` GitHub release](https://github.com/onyx-dot-app/onyx/releases?q=cli%2Fv).

### Build from Source

Requires [Go 1.27+](https://go.dev/dl/).

```shell
git clone --depth 1 https://github.com/onyx-dot-app/onyx.git
cd onyx/cli
go build -o onyx-cli .
sudo mv onyx-cli /usr/local/bin/
```

## Setup

Launch the interactive chat TUI — on first run it guides you through setup:

```shell
onyx-cli chat
```

This prompts for your Onyx server URL and personal access token (PAT), tests the connection,
and saves config to `~/.config/onyx-cli/config.json` (or `$XDG_CONFIG_HOME/onyx-cli/config.json` if set).
To reconfigure later, use the `/configure` slash command inside the TUI.

### Generating an Access Token

Navigate to **Settings > 3rd Party Access > Access Tokens** (`/app/settings/third-party-access`)
and select **New Access Token** to create an access token for the CLI.

<Note>
  On Onyx Cloud, access tokens require an active paid subscription.
</Note>

### Environment Variables

Environment variables override config file values.

| Variable | Required | Description |
|----------|----------|-------------|
| `ONYX_SERVER_URL` | No | Server base URL (default: `https://cloud.onyx.app`) |
| `ONYX_API_PREFIX` | No | API path prefix (default: `/api`) |
| `ONYX_PAT` | No | Personal access token for authentication (required if no config file) |
| `ONYX_PERSONA_ID` | No | Default Agent ID |
| `ONYX_STREAM_MARKDOWN` | No | Turn progressive Markdown rendering on or off (`true` or `false`) |

### Validate Configuration

Verify that your configuration is correct and the server is reachable:

```shell
onyx-cli validate-config
```

| Command | Description |
|---------|-------------|
| `onyx-cli chat` | Launch the interactive chat TUI (includes first-time setup) |
| `onyx-cli ask` | Ask a one-shot question (non-interactive) |
| `onyx-cli search` | Search company knowledge and return ranked documents |
| `onyx-cli agents` | List available Agents |
| `onyx-cli document-sets` | List the Document Sets you can search |
| `onyx-cli image` | Generate or edit images with the configured image provider |
| `onyx-cli validate-config` | Validate configuration and test connection |
| `onyx-cli install-skill` | Install the Onyx CLI skill file for AI coding agents |

| `onyx-cli deploy` | Install and manage a self-hosted Onyx deployment |

Use `--version` to print the client and server versions, and `--debug` for verbose logging.

### Interactive Chat

```shell
onyx-cli chat
```

Use `--agent-id` or `--agent-name` to start the session with a specific Agent,
and `--no-stream-markdown` to turn off progressive Markdown rendering.

#### Tool approvals

Some tool calls need your approval before they run, for example an MCP Action with the **Ask** policy.
The chat shows a card with the tool name and its arguments. The request waits until you decide. It has no time limit.

| Key | Action |
|-----|--------|
| `y` | Approve once |
| `a` | Approve for this session |
| `n` | Reject |
| `d` | Show all arguments in full, or the short list again |
| `Up` / `Down`, `Enter` | Select and confirm an action |
| `Escape`, `Ctrl+C` | Stop the response while it runs |

The card shows at most 10 arguments and shortens long values. Press `d` to read every argument before you decide.

The shortcuts work when the input is empty. After the decision, the card changes to a one-line record: **Approved**,
**Approved for this session**, **Not approved**, **Disabled**, or **No longer waiting**.
When the server continues the response, the chat shows the rest of it.

While a request waits, the response is paused on the server. A paused response cannot be stopped,
so `Escape` and `Ctrl+C` do nothing to it; decide each request instead.
If you stop a running response while a request is open, Onyx rejects the request, and the record shows **Not approved**.
You can quit the chat and decide later: if you open the session with `/resume`,
the chat shows the response with its card. If you send a message while the response waits, Onyx refuses it:
the chat keeps your message as a draft and shows the card. If the connection to a running response drops,
the chat connects to it again.

A request from a background agent names the agent, for example `triage wants to run Create issue`.
It does not pause the chat: you can send messages while it waits, and its card stays after the response ends or stops.
After you decide, the chat shows the outcome and the agent's later requests.

#### Questions from the Agent

The Agent can ask you 1 to 3 questions when your answer changes its work.
The chat shows a card that asks each question in turn, with its choices and an **Other** row.
The response waits until you answer. It has no time limit.

| Key | Action |
|-----|--------|
| `Up` / `Down`, `Enter` | Select and confirm a choice |
| Type a choice's number, `Enter` | Choose that choice |
| `Enter` on **Other** | Type your own answer in the input, then press `Enter` |
| Type a reply, `Enter` | Answer every question of the response with your reply |
| `Escape` | Go back from **Other** to the choices |

After the last question, the chat sends your answers, and the card changes to a record of them.
A reply that you type shows as your message under the record. If a tool call of the response also waits for approval,
decide it first. If you stop a running response before you answer, the record shows **Not answered**. As with approvals,
a waiting response cannot be stopped, and `/resume` shows the card again.

### One-Shot Questions

Ask a question and get a response without entering the TUI:

```shell
onyx-cli ask "What is our company's PTO policy?"
```

Use `--agent-id` to target a specific agent:

```shell
onyx-cli ask --agent-id 5 "Summarize our Q4 roadmap"
```

| Flag | Description |
|------|-------------|
| `--agent-id <int>` | Agent ID to use (overrides default) |
| `--agent-name <string>` | Agent name to use (exact or unique substring) |
| `--json` | Output NDJSON events instead of plain text |
| `--prompt <string>` | Question text, for use with piped stdin context |
| `--quiet` | Buffer output and print once at the end |
| `--max-output <int>` | Max bytes before truncating (0 to disable) |
| `--approve <answer>` | Answer to tool approval requests when `ask` cannot prompt: `fail` (default), `reject`, `once`, or `session` |
| `--questions <answer>` | Answer to the Agent's questions when `ask` cannot prompt: `fail` (default) or `skip` |

When a tool call needs approval and stderr is a terminal, `ask` shows the request on stderr and prompts: `[y]
approve once / [a] approve for session / [d] show all arguments / [N] reject`.
The request shows at most 10 arguments and shortens long values. Answer `d` to show every argument in full,
then answer the prompt again. If the server ends the request first,
for example because the program that made the call ended, the prompt ends and `ask` shows the outcome.
`ask` ignores input that you typed before the prompt showed. When the response continues after the answers,
`ask` follows it and prints the rest of the answer. It does not print again the text, tool,
or search lines that it already printed. If you interrupt `ask` at a prompt while the response waits,
`ask` exits with code `11` without a decision. The request keeps waiting, and you can decide it in another client,
for example with `/resume` in `onyx-cli chat`. An interrupt while the response still runs stops it.

Without a terminal, in CI, or with `--json`, `ask` does not wait for input. It uses `--approve` instead:

- `fail` rejects the tool call, prints the rest of the answer, and exits with code `10`.
- `reject` rejects the tool call and continues the response without it.
- `once` and `session` approve every tool call in the response that needs approval.

If you set `--approve`, `ask` uses it on a terminal too.

When the Agent asks questions and stderr is a terminal, `ask` shows each question with its numbered choices on stderr.
Then it prompts for the answer. For a question with three choices, the prompt is:

```text
[1-3] choose an option / type your own answer / [Enter] no answer
```

Type a number to choose, or type your own answer. An empty answer tells the Agent that you have no answer.

Without a terminal, in CI, or with `--json`, `ask` uses `--questions` instead.
Both values tell the Agent that no one can answer, so it continues with its own judgment:

- `fail` prints the rest of the answer and exits with code `12`.
- `skip` prints the rest of the answer and exits normally.

If you set `--questions`, `ask` uses it on a terminal too.

### Search Documents

Search your indexed knowledge and get ranked documents without an answer:

```shell
onyx-cli search "deployment rollback procedure"
onyx-cli search --source slack,google_drive --days 30 "release checklist"
onyx-cli search --document-set "Engineering Wiki" "on-call runbook"
```

| Flag | Description |
|------|-------------|
| `--source <list>` | Filter by source type (comma-separated, such as `slack,google_drive`) |
| `--document-set <name>` | Filter by Document Set name (repeat the flag for more than one) |
| `--days <int>` | Only return results from the last N days |
| `--agent-id <int>` / `--agent-name <string>` | Search with an Agent's knowledge scope |
| `--raw` | Output the full API response |
| `--no-query-expansion` | Skip query expansion (faster, less comprehensive) |

### Generate Images

```shell
onyx-cli image generate --prompt "A diagram of our deployment pipeline" --output pipeline.png
onyx-cli image edit --input-image logo.png --prompt "Make the background transparent"
```

Image commands use the image generation provider your admin configured in Onyx.

### List Agents

```shell
onyx-cli agents
onyx-cli agents --json
```

Prints a table of available Agent IDs, names, and descriptions.

### List Document Sets

```shell
onyx-cli document-sets
onyx-cli document-sets --json
```

Prints the IDs, names, and descriptions of the Document Sets you can search.
Use the names with `onyx-cli search --document-set`.

### Serve over SSH

Share the chat TUI with people who do not have the CLI installed:

```shell
onyx-cli serve --host 0.0.0.0 --port 2222
```

Users connect with `ssh your-host -p 2222` and paste their own personal access token at the login prompt.

### Self-Hosted Deployment

The `deploy` command group installs and manages a self-hosted Docker Compose deployment of Onyx — a guided installer
plus `upgrade`, `status`, `logs`, `stop`, and `uninstall` commands:

```shell
onyx-cli deploy install
```

## Using as an AI Coding Assistant Skill

The Onyx CLI can be used as a tool by AI coding assistants (such as Claude Code and Cursor)
to query your knowledge base directly from within your development environment.
Install the bundled skill file into your project so your coding agent can discover the CLI:

```shell
onyx-cli install-skill
onyx-cli install-skill --global
onyx-cli install-skill --agent claude-code
```

The skill is written to `.agents/skills/onyx-cli/`. Use `--global` to install it in your home directory,
`--copy` to copy files instead of symlinking, and `--agent` to target a specific agent's skill directory.
You can also read it in the Onyx repository at
[`cli/internal/embedded/SKILL.md`](https://github.com/onyx-dot-app/onyx/blob/main/cli/internal/embedded/SKILL.md).

### When the skill is invoked

The skill is triggered when you ask your AI assistant about:

- Company-specific information (policies, processes, documentation)
- Internal knowledge bases or connected data sources
- Anything referencing Onyx, "search Onyx", or querying company documents

It is **not** used for general programming questions or questions about code in the current repository.

### Non-interactive behavior

When the CLI runs without a terminal, for example from an AI agent or a pipe,
it prints results to stdout and progress to stderr, uses no ANSI codes or prompts,
and truncates long `ask` output at 50000 bytes (use `--max-output 0` to disable). Exit codes identify the failure:
`3` not configured, `4` authentication failed, `5` server unreachable, `6` rate limited,
`10` a tool call needed approval and `ask --approve=fail` rejected it,
`11` `ask` was interrupted at an approval or question prompt and the request still waits,
`12` the Agent asked questions and `ask --questions=fail` answered that no one can answer.

### Configuration for agents

Run `onyx-cli chat` once to complete first-time setup, or set environment variables,
which override the config file and are useful for CI/CD or sandboxed environments:

```shell
export ONYX_SERVER_URL="https://your-onyx-server.com"
export ONYX_PAT="your-pat"
```

### JSON output for structured parsing

Use `--json` to get NDJSON event output, which is easier for agents to parse programmatically:

```shell
onyx-cli ask --json "List all active API integrations"
```

| Event Type | Description |
|------------|-------------|
| `message_delta` | Content token — concatenate all `content` fields for the full answer |
| `stop` | Stream complete. With `stop_reason` `awaiting_user`, the response waits for the user, and its later events follow after them |
| `error` | Error with `error` message field |
| `search_tool_start` | Onyx started searching documents |
| `citation_info` | Source citation with `citation_number` and `document_id` |
| `tool_approval_request` | A tool call waits for approval. `ask` answers it with `--approve` |
| `tool_approval_resolved` | How an approval request ended, in `outcome` |
| `tool_question_request` | The Agent asks questions. `ask` answers them with `--questions` |
| `tool_question_resolved` | How the questions ended, in `outcome`, with the `answers` |
