Skills teach Onyx **how to do a kind of work**. In main chat, Skills provide Markdown instructions without a sandbox.
In Craft, Skills can also provide scripts, templates, and other files for the session sandbox.

For example, a slide skill can tell Craft how to choose layouts, apply a template, validate the finished deck,
and save the presentation in the right format. You provide the goal and source material; the skill provides the method.

<Note>
  Skills do not connect external accounts or hold credentials. To let Craft read from or act in tools like Slack, Gmail,
  or GitHub, connect an [App](/overview/core_features/craft_apps).
</Note>

## Use Skills in main chat

Open **Skills** in the main sidebar. Create, upload, or enable a custom or marketplace Skill there.
The library and editor work when Craft is disabled. Keep **Skills** selected in the chat's tools.
Ask Onyx to use the Skill by name, or describe a task that matches its description. For a custom Agent,
turn on **Skills** in the Agent editor. Default chat includes this tool after the server migration.
Admins can turn it off in **Chat Preferences → Actions & Tools**.

The model can request a page of Skill names and descriptions, then read one Skill's `SKILL.md` when needed.
It can also read supporting `.md` files by their paths inside that Skill.
Onyx does not put every Skill's instructions into the prompt.

Main chat uses the same access, enabled choices, installation policies, current versions,
and app readiness as Skill delivery. Personal, company, directly shared, group-shared,
and marketplace Skills can qualify. For duplicate names, the company library takes priority, then your library,
then other shared libraries. An oversized selected Skill is refused; it does not select a different same-name Skill.
If a bundle is unreadable, Onyx tries the next eligible Skill. Supporting files come from the selected bundle.

Each discovery and read checks current access. Removing access, disabling a Skill, or retiring it prevents new reads.
Content already present in conversation history remains there, including earlier Skill lists and instructions.
Resumed agents use the tools allowed by the current request.

| Main chat limit | Behavior |
| --- | --- |
| Discovery | Up to 20 names per page, with descriptions limited to 160 characters. Each page stays within 8 KiB. |
| Markdown | Each source file must fit within 16 KiB of UTF-8 text, including frontmatter. Larger files are refused. |
| Bundle metadata | The ZIP central directory must fit within 1 MiB. Stored and expanded bundle limits still apply. |
| Supporting files | Only `.md` files inside the same bundle. Absolute paths, traversal paths, and symlinks are refused. |

Split long instructions into short Markdown files and link them from `SKILL.md`.
These model context limits are separate from the Skill filesystem allowance.

### Capabilities and execution

Main chat reads custom and marketplace Markdown as reference material. A Skill cannot grant tools or permissions.
The reader does not execute scripts, extract files, or mount a Skill directory.
The Python tool does not provide a mounted Skill sandbox.
Script execution still requires an existing authorized execution capability and its normal access checks.
Use Craft for workflows that depend on mounted Skill scripts and assets.

The packaged built-ins currently require Craft capabilities and are excluded from main chat's Skill reader:

- `pptx` requires its mounted scripts, dependencies, and output directories.
- `company-search` and `image-generation` require `onyx-cli`.
- `browser` requires Craft's browser CLI and session environment.
- `craft-documentation` uses Craft's `webfetch` tool.
- Connected-app built-ins require their helpers, credentials, action policies, and rendered template values.

This exclusion does not disable main chat's own search, image, or connected tools.
Those tools remain available according to the Agent and request settings.

## How Craft uses skills

Craft can choose an available skill automatically when your request matches its description.
You can also select one explicitly when you want Craft to follow a particular workflow.

<Steps>
  <Step title="Choose a skill">
    In a Craft session, select **+**, then **Skills**, and choose a skill.
    You can also type **/** followed by the skill name.
  </Step>

  <Step title="Describe the result">
    Tell Craft what to produce and provide the audience, source material, and requirements that matter.
    Selecting a skill does not replace a clear prompt.
  </Step>
</Steps>

| Goal                            | How to use a Skill                                                                                                                         |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **Build a presentation**        | Select the `pptx` Skill, attach a company deck as a template, and ask Craft to build a presentation from your source material.             |
| **Search company knowledge**    | Ask a company-specific question and let the `company-search` Skill retrieve information you already have permission to access.             |
| **Navigate a website**          | Select the Browser Skill and ask Craft to open a site, follow links, interact with pages, or take screenshots.                             |
| **Generate a visual**           | Select the image generation Skill and describe the subject, composition, style, aspect ratio, and where the visual will be used.           |
| **Standardize repeatable work** | Use a custom Skill to capture your team's process for reports, briefs, reviews, or another workflow you want Craft to repeat consistently. |

## Browse and inspect skills

Open **Skills** from the main sidebar to browse custom and marketplace Skills available to you.
To browse built-in Skills, open **Skills** from the Craft sidebar.
Select a skill card to preview its instructions before using it.

| Label           | What it means                                                                                |
| --------------- | -------------------------------------------------------------------------------------------- |
| **Built-in**    | Maintained by Onyx. Availability can depend on your deployment and configured providers.     |
| **Custom**      | Created in your organization and shared with you, your group, or everyone.                   |
| **Personal**    | Created and owned by you. It starts private, but you can share it if your permissions allow. |
| **Unavailable** | Visible for reference, but Craft cannot use it until its dependency is configured.           |

Built-in skills cover presentations (`pptx`), company search, image generation, website navigation (Browser),
and Craft documentation. Each connected [App](/overview/core_features/craft_apps) also brings its own Skill.
The exact list you see depends on what your organization has enabled.

<Tip>
  A skill's description tells Craft when to use it. If Craft repeatedly misses a custom skill,
  make the description concrete about the tasks it covers, or select the skill explicitly in your prompt.
</Tip>

## Create a personal skill

Create a personal Skill when you have instructions, examples, or reference files you want to reuse across sessions.
Open **Skills**, select **Add**, then choose how you want to begin:

| Starting point | Choose | What happens |
| --- | --- | --- |
| You want to write the Skill in Onyx | **Create a skill** | The Skill editor opens so you can write the details and instructions, then add supporting files. |
| You already have a Skill | **Upload a skill** | Upload `SKILL.md`, a ZIP, or a Skill folder. Onyx reads the instructions and creates the Skill for you. |
| The Skills live in a GitHub marketplace | **Sync from GitHub** | Preview the catalog, then request a sync. The source stays available for later updates. |

Uploaded and authored Skills start personal and private. After creation, you can share them from the Skill editor.
Global skill managers can also create company marketplaces with explicit access defaults.

### Create a skill

<Steps>
  <Step title="Add the details">
    Enter a name and describe when Craft should use the Skill. Onyx uses the name to create the Skill's identifier,
    converting spaces and punctuation to hyphens when needed.
  </Step>

  <Step title="Write the instructions">
    Describe the workflow Craft should follow, including important constraints, expected outputs, and checks.
  </Step>

  <Step title="Add supporting files">
    Add references, examples, templates, scripts, or assets under **Supporting files**. You can select files or a ZIP,
    or drag in a folder. Onyx unpacks ZIP files and preserves the directory structure.
  </Step>

  <Step title="Create the Skill">
    Select **Create**. Onyx saves the instructions as `SKILL.md` and opens the Skill editor.
  </Step>
</Steps>

<Info>
  If you already have a Skill,
  use **Import skill** at the top of the creation page to fill in the form and add its files.
  If you have already entered content, Onyx asks before replacing the name, description, instructions,
  and supporting files with the imported Skill.
</Info>

### Upload an existing Skill

Upload `SKILL.md` directly when the Skill contains instructions only. When it includes supporting files,
upload a ZIP or drag in a folder with `SKILL.md` at the top level.

Plugin ZIP upload is not supported yet. Upload one Skill bundle, not a plugin package.
The Plugins page connects apps and services; it does not accept plugin ZIPs.

```text
weekly-customer-update/
├── SKILL.md
├── examples/
│   └── finished-update.md
└── templates/
    └── update-template.md
```

At minimum, `SKILL.md` needs a name and description in YAML frontmatter, followed by the instructions Craft should use:

```md
---
name: Weekly customer update
description: Create a concise weekly customer update from meeting notes and account activity.
---

# Weekly customer update

1. Summarize material changes since the previous update.
2. Separate customer decisions, open risks, and next steps.
3. Name an owner and due date for every next step.
4. Follow the format in `templates/update-template.md`.
```

<Steps>
  <Step title="Prepare the bundle">
    Put the instructions in `SKILL.md` and keep supporting files in the same folder. For a folder or ZIP,
    use a lowercase, hyphenated name such as `weekly-customer-update`; that name becomes the Skill's identifier.
    For a standalone `SKILL.md`, Onyx creates the identifier from its frontmatter `name`.
  </Step>

  <Step title="Upload the Skill">
    Open **Skills**, select **Add** > **Upload a skill**, and select `SKILL.md` or a ZIP. For one Skill,
    review the editor and configure **Edit sharing** before creating it. To import several Skills together,
    select multiple ZIP files. Each ZIP must contain one Skill. Configure access once for the batch before importing it.
  </Step>
</Steps>

### Sync from GitHub

Select **Add** > **Sync from GitHub**. Enter a name, repository owner, repository name, and branch, tag, or commit.
Enter a folder if the marketplace catalog is below the repository root. Connect GitHub when prompted.
Select **Preview** to review ready, blocked, and unsupported entries. A missing catalog shows a sample you can add.
Select **Request sync** to save the source and start its first sync.

**Sync requested** means the request was saved. Skills appear after the background sync completes.
The **Marketplaces** list shows progress and errors, including sources with no imported Skills.
Open a source to request another sync, replace its GitHub login, or review a retirement proposal.

Skills from the previous one-time GitHub import remain editable custom Skills.
Add their repository as a marketplace to sync new copies with repository updates.
The old `/skills/github/preview` and `/skills/github/import` API routes are removed.
Change synced instructions and files in GitHub, then sync again. Their Onyx content page is read-only.

### Update a Skill

Open a personal Skill to edit its description or instructions. Its name stays fixed after creation.
Under **Supporting files**, you can:

- Add individual files, ZIP files, or folders. New files are added to the existing bundle, and matching paths are
  replaced.
- Browse the bundle as a directory tree and remove files you no longer need. `SKILL.md` cannot be removed.
- Upload content that includes `SKILL.md` to replace the description, instructions, and files. Onyx asks
  you to confirm before replacing the existing Skill content.

Changes are synchronized to people who can use the Skill. You can also disable the Skill without deleting it,
change its sharing, transfer ownership, or delete it.

### Share a Skill

Custom Skill cards show **Personal**, **Shared**, or **Organization** access.
**Shared** means specific people or groups have access. **Organization** means everyone in the organization has access.

Open a Skill to view its instructions. Users who can manage sharing can switch between **Details** and **Sharing**.
Company synced Skills require global skill management or group management within the Skill's existing group scope.
Other editors get a read-only preview. Personal synced owners control the audience;
global managers can change installation settings.
Company access and installation settings require global manage-skills permission, even for owners.
This applies during creation, ZIP upload, and later sharing changes. For uploaded Skills with an owner,
owners and editors can manage individual access. Group sharing follows their group permissions.
Editing a public Skill without global permission preserves its organization access.
Bulk sharing shows **Keep unchanged** when you cannot change organization access.
Choose who can use it and give each person or group **Can use** or **Can edit** access. Under **Installation**,
choose how the Skill is installed for people with access:

| Option | Effect |
| --- | --- |
| **Available to install** | People can install or uninstall the Skill at any time. |
| **Installed by default** | Onyx installs the Skill automatically. People can disable or uninstall it. |
| **Required** | Onyx installs the Skill automatically. People cannot disable or uninstall it. |
| **Not available** | The Skill cannot be enabled or loaded unless a group override makes it available. Owners and direct recipients can still see it. |

Your Skill card shows **Required** when your effective setting requires it, including a group override.

### View and restore versions

<img className="rounded-image" src="/assets/overview/core_features/skill_versions.webp" alt="The Versions tab with the current Skill version, an earlier version, and preview and restore actions"/>

Owners and editors can open a custom Skill and select **Versions**, including from an App's **Skills** tab.
Each entry shows its number, change, creator, and date.
Select **Preview** to inspect retained instructions and file paths.
Entries without retained files have no preview or restore action.
Viewers and built-in Skills have no version history tab. For a retired Skill,
open its marketplace and select **Versions**. The personal owner or a global Skill manager can inspect retained history.
Restore remains unavailable.

Select **Load older versions** to see earlier entries. If loading fails,
the current entries stay visible and **Retry** loads them again. If Onyx denies access,
it hides the saved history and closes any version preview. On a phone,
scroll inside the dialog to reach each entry's actions.

Select **Restore** beside an earlier version, then confirm **Restore** to replace current content.
Changed content creates a new version. Identical content does not add a version. Sharing settings stay the same.
Restore refreshes loaded history and keeps the oldest displayed entry visible.
Unsaved sharing changes stay in the dialog. Synced Skills show their source revision.
Update their GitHub source instead of restoring them locally.
Save or discard unsaved editor changes before restoring a version. Preview remains available.

### Manage several Skills

Select Skills with the checkboxes on their cards to share, enable, disable, or delete them together.
**Enable for me** and **Disable for me** affect your library only.
See [Manage several Skills](/admins/managing_features/craft_skills#manage-several-skills) for the admin steps.

<Warning>
  Never put passwords, API keys, tokens, or production credentials in a skill bundle.
  Use [Apps](/overview/core_features/craft_apps) for authenticated access to external services.
  Review every script and file before uploading a bundle you did not create.
</Warning>

## Write limits

A change that increases enabled Skills can exceed the per-user limit of 500 MiB or 5,000 files.
Onyx refuses the change and explains the failed limit where you made it. The message gives your proposed total,
when applicable, and the number of other affected users. Unknown sizes appear as estimates.
The server checks the limit for each write.

Refused saves keep your editor or sharing draft. Bulk actions keep failed Skills selected for retry.
For multiple ZIP uploads, each refused ZIP shows its limit message. Successful imports remain saved.
A refused restore keeps its confirmation open. Limit notifications remain until dismissed;
another refusal replaces the previous notification. Turn off Skills you do not need, reduce their content,
or adjust sharing, then retry.

A marketplace lists each blocked entry with the failed limit and affected user count.
Other sync errors keep their original explanation. A later sync retries blocked entries.

## App Skills that stay off

An App connection can succeed while some associated Skills exceed your write limit. The App remains connected.
Its details list the Skills that stayed off and your current usage.

Make space, then use **Review skills** to turn on Skills with an available switch.
If other blocked Skills need a reconnect, both actions remain available.
For a Required or built-in Skill on your own connection, select **Disconnect to reconnect** below the warning.
Confirm **Disconnect**, then connect the App again. Disconnecting stops tools that use that connection.
The warning disappears when the Skills fit. A setup card links to **Manage skills** after connection.

## Skill usage API

`GET /api/skills/limit/me` returns measured usage and the totals used to check write limits.
`charged_bytes` and `charged_files` include an allowance for each Skill whose size is unknown.
`unknown_skill_count` identifies these estimates. The response also includes `max_bytes` and `max_files`.

`GET /api/skills/limit/users` requires global Manage Skills and lists users above a write limit.
Each row includes the omission count from the last successful delivery. A null count means no delivery is recorded.
This count does not predict the next delivery.

A refused write returns HTTP 413 with `skill_limit`: the failed limit, affected user count,
and your proposed usage when applicable. Bulk failures include the same nullable field for each refused Skill.
Ordinary errors retain their normal explanation.

## Session limits

Craft loads whole Skills within 900 MiB, 10,000 files, and 10,000 folders per session.
Each file must fit within 25 MiB or the configured upload limit, whichever is smaller.
This limit applies after instruction placeholders expand and includes supporting files.
Each file counts as at least 4 KiB. A file path can use at most 4,021 UTF-8 bytes.
Each file or folder name can use at most 255 UTF-8 bytes.

Craft keeps built-in Skills first, then Required Skills, then Skills you enabled, then Skills installed by default.
Within each group, more recent choices or grants come first. Skills with unknown dates come last.
If a Skill does not fit, Craft leaves it out and tries the remaining Skills.
Stored content and your saved choices stay unchanged. Turn off Skills you do not need, or reduce their size,
then reload or start a session.

### Session API

Session and reload responses include `skill_runtime_notice` when a Skill did not load. The notice lists omitted Skills,
their charged sizes, file counts and the limit that failed. It describes the last successful delivery.
Failed delivery preserves the previous notice. Only the session owner's sandbox supplies this notice.
If every Skill fits, the field is null.

## Troubleshooting

<AccordionGroup>
  <Accordion title="A skill is missing from the picker">
    Confirm the skill is enabled and shared with you. Unavailable built-in skills do not appear in the session picker.
    If the skill depends on a model or deployment feature, ask an admin to configure that dependency.
  </Accordion>

  <Accordion title="Craft says that some skills did not load">
    All skills in a Craft session must fit in 900 MiB and 10,000 files. When they do not fit,
    Craft leaves out whole skills and shows an error at the start of the session.
    The session also allows at most 10,000 folders. Each file path can use at most 4,021 UTF-8 bytes.
    Each file or folder name can use at most 255 UTF-8 bytes.
    A skill that exceeds a folder or path limit is also left out. The error identifies that limit.
    The error lists each skill that did not load and its size. Craft keeps built-in skills first, then Required skills,
    then skills that you turned on, then skills installed by default.
    Select **Manage skills** and turn off the skills that you do not need, or make a skill smaller.
    Then start a new session or reload the session. Select **Dismiss** to close the error.
    A dismissed error stays closed until the omitted skills or limits change, or all skills fit again.
    Leaving the session hides the error. An undismissed error returns when you reopen that session.
    If skills changed during the session, reload them before Craft shows the new omissions.

    <img className="rounded-image" src="/assets/overview/core_features/skill_runtime_notice.webp" alt="Craft identifies a Skill with a path that is too long and offers Manage skills and Dismiss"/>
  </Accordion>

  <Accordion title="My Skill will not upload">
    Keep one Skill in each ZIP. You can upload several ZIP files together.
    Put `SKILL.md` at the top level of the folder. In a ZIP,
    place it at the archive root or directly inside one enclosing folder.
    Confirm that its frontmatter contains non-empty `name` and `description` fields. For a folder or ZIP,
    check that its name is lowercase and hyphenated. If you started from scratch, try a different Skill name.
    A custom Skill cannot use the same identifier as an existing or built-in Skill.
  </Accordion>
</AccordionGroup>

## Marketplace creation

If company-management access is removed, clear **Company Marketplace** to continue with a personal source.
Your source fields stay.

## Marketplace details

Select **Marketplace details** on a source to inspect its sync status and Skills.
Press **Escape** to close the dialog and return keyboard focus to the opening control.
Leaving the marketplace list closes the dialog. Returning to the list does not reopen it.
